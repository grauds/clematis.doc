The motivation is to both make build faster and more reliable due to less network latency. Also
to avoid issues with the availability of some external resources over time, either due to network
access policies or their deprecation.

## Nexus
The free version of Nexus is able to host NPM repositories proxies, so I use it for React and Angular 
frontends.

### Installation in Proxmox VM

On Proxmox Nexus VM ran:
```bash
sudo docker run -d  \
   -p 8081:8081 \
   --name nexus \
   --restart always \
   -v nexus-data:/nexus-data \
  sonatype/nexus3:latest
```
Copied the autogenerated password to use for the first login in Nexus Web UI:
```bash
sudo docker exec -it nexus cat /nexus-data/admin.password
```
Created a remote repository named `npm-proxy` and added the repository URL to Jenkins credentials
as a text note.

### Jenkins Pipeline

Added the URL to the Jenkins pipeline as an argument to Docker build, for example:

```jenkins title="Jenkinsfile"
stage('Build Docker Images') {
  steps {
    withCredentials([
      string(credentialsId: 'NEXUS_NPM_URL', variable: 'NEXUS_NPM_URL')
    ]) {
      sh """
        docker build \
          . -t money.tracker.ui -f Dockerfile \
          --build-arg="ENVIRONMENT=uat" \
          --build-arg="NPM_REGISTRY=${NEXUS_NPM_URL}"
      """
    }
  }
}
```

### Nx Angular Project

Once Docker gets the URL, it will use it to configure the fetching of packages regardless of 
packages resolution information contained in `package-lock.json` file:

```dockerfile
COPY .babelrc eslint.config.mjs decorate-angular-cli.js \
     jest.config.ts jest.preset.js nx.json postcss.config.json .postcssrc.json \
     package.json package-lock.json tsconfig.base.json ./

ARG NPM_REGISTRY=https://registry.npmjs.org/
ENV NPM_CONFIG_REGISTRY="${NPM_REGISTRY}"

RUN npm ci  --no-audit --no-fund
```

So the project files themselves are not modified in any way.

:::note
The Angular project has pretty modestly counted towards 1,413 artifacts out of 40,000 free usage limits. 
The number of requests a build made was about 5,000, which is acceptable since it is allowed to 
make 100 thousand requests per day, which gives about 20 free builds.
:::

## Artifactory

The OSS version of Artifactory doesn't support npm packages, so I installed it to proxy Java repositories.

### Installation in Proxmox VM

Created a unique `MASTER_KEY` with:

```bash
export MASTER_KEY=$(openssl rand -hex 16)
```

There should be `jfrog/artifactory/var` and `jfrog/postgres/data`
directories created for Artifactory and Postgres data:

```bash
anton@artifactory:~$ ls -l
total 20
-rw-rw-r-- 1 anton anton 1121 Apr  2  2026 docker-compose.yml
drwxrwxr-x 4 anton anton 4096 Apr  2  2026 jfrog
```

On Proxmox Nexus VM created a docker-compose file:

```docker-compose
services:
  postgres:
    image: postgres:15-alpine
    container_name: postgres
    environment:
      POSTGRES_DB: artifactory
      POSTGRES_USER: artifactory
      POSTGRES_PASSWORD: password
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U artifactory -d artifactory"]
      interval: 5s
      timeout: 5s
      retries: 5
    volumes:
      - ~/jfrog/postgres/data:/var/lib/postgresql/data

  artifactory:
    image: releases-docker.jfrog.io/jfrog/artifactory-oss:latest
    container_name: artifactory
    depends_on:
      postgres:
        condition: service_healthy
    ports:
      - "8081:8081"
      - "8082:8082"
    environment:
      JF_SHARED_DATABASE_TYPE: postgresql
      JF_SHARED_DATABASE_DRIVER: org.postgresql.Driver
      JF_SHARED_DATABASE_URL: jdbc:postgresql://postgres:5432/artifactory
      JF_SHARED_DATABASE_USERNAME: artifactory
      JF_SHARED_DATABASE_PASSWORD: password
      JF_SHARED_SECURITY_MASTERKEY: 5b54a897974e51c087826ba34ae22350
      JF_JFCONNECT_ENABLED: "false"
      JF_SHARED_NODE_IP: "192.168.1.174"
    volumes:
      - ~/jfrog/artifactory/var:/opt/jfrog/var
```
Started both services with Docker Compose:

```bash
docker compose up -d
```
Created remote repositories named `maven-proxy` and `gradle-plugins-remote`, 
generated a key for the repository with the 'Set Me Up' function,
for example, **`cmVmd...`**
and added it with the repository URL to Jenkins credentials as text notes. 
The key can be revoked in the Artifactory UI as well.

### Gradle Project

For local Gradle development it is possible to tell Gradle to use the credentials by placing them
into the local `gradle.properties` file, which should not be checked into version control: 

```proprties title="gradle.properties"
artifactory_user=admin
artifactory_password=cmVmd...
```

The repositories' management is best done in `settings.gradle`, for example:

```gradle title="settings.gradle"
pluginManagement {
    repositories {
        def useArtifactory = System.getenv("USE_ARTIFACTORY") == "true"
        if (useArtifactory) {
            maven {
                url "http://192.168.1.174:8082/artifactory/maven-central-proxy"
                allowInsecureProtocol = true
                credentials {
                    username = providers.gradleProperty("artifactory_user").orNull ?: System.getenv("ARTIFACTORY_USER")
                    password = providers.gradleProperty("artifactory_password").orNull ?: System.getenv("ARTIFACTORY_PASSWORD")
                }
            }
            maven {
                url "http://192.168.1.174:8082/artifactory/gradle-plugins-remote"
                allowInsecureProtocol = true
                credentials {
                    username = providers.gradleProperty("artifactory_user").orNull ?: System.getenv("ARTIFACTORY_USER")
                    password = providers.gradleProperty("artifactory_password").orNull ?: System.getenv("ARTIFACTORY_PASSWORD")
                }
            }
        } else {
            // Default fallback for local machine dev and GitHub Actions
            gradlePluginPortal()
            google()
        }
    }
}

dependencyResolutionManagement {
    repositories {
        // Check if the pipeline explicitly requested Artifactory
        def useArtifactory = System.getenv("USE_ARTIFACTORY") == "true"
        if (useArtifactory) {
            maven {
                url "http://192.168.1.174:8082/artifactory/maven-central-proxy"
                allowInsecureProtocol = true
                credentials {
                    username = providers.gradleProperty("artifactory_user").orNull ?: System.getenv("ARTIFACTORY_USER")
                    password = providers.gradleProperty("artifactory_password").orNull ?: System.getenv("ARTIFACTORY_PASSWORD")
                }
            }
        } else {
            // Fallback for GitHub Actions
            mavenCentral()
        }
    }
}
```
The Artifactory URL can be not hidden with Jenkins credentials, it is not a secret either.
The switcher here is `USE_ARTIFACTORY` environment variable. If it is not set,
Gradle will use the Maven Central repository, like in the case of GitHub Actions builds.

### Jenkins Pipeline

The following lines will wrap the Gradle build:
```jenkinsfile
stage('Gradle Build') {
    steps {
        withCredentials([usernamePassword(credentialsId: 'artifactory-admin-token',
                                         passwordVariable: 'ARTIFACTORY_PASSWORD',
                                         usernameVariable: 'ARTIFACTORY_USER')]) {
            withEnv(['USE_ARTIFACTORY=true']) {
                sh './gradlew clean build'
            }
        }
    }
}
```
And the example local build:

```bash
export USE_ARTIFACTORY=true & ./gradlew clean build
```
